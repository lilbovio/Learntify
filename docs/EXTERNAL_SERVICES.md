# External services and the zero-dollar operating envelope

Verified October 22, 2026. These are provider allowances, not a guarantee of capacity or uptime. No accounts, deployments, purchases, OAuth registrations or live emails were created during implementation. Keep billing plans free; do not enable paid upgrades or overages automatically.

## Accounts needed before public launch

1. **Cloudflare account — Free.** Hosts DNS, TLS, static client files, Worker API and D1. Static asset requests are free and unlimited when served directly as assets; API requests use the Workers allowance. Workers Free currently permits 100,000 requests/day and 10 ms CPU/invocation. Auth CPU usage must be measured on the deployed runtime before launch. Local tests cannot prove this allowance is sufficient. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)
2. **Cloudflare D1 — Free with capacity limits.** 5 million rows read/day, 100,000 rows written/day, 5 GB total account storage, but only **500 MB per database** on Free. Index maintenance counts as writes. Seven-day Time Travel fits the initial recovery-window target, but a tested restore procedure and deletion replay are still needed. Keep D1 as the single authoritative database; MongoDB is not required. [Pricing](https://developers.cloudflare.com/d1/platform/pricing/) · [Limits and recovery](https://developers.cloudflare.com/d1/platform/limits/)
3. **GitHub account/public repository — Free.** Source, issues, pull requests and CI. Standard GitHub-hosted runners are free for public repositories; larger runners and other metered features are excluded from this plan. Configure cache/artifact retention conservatively. The current workflow does not deploy. This same account can register the GitHub sign-in OAuth application; request only identity/email access, not repository permissions. [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions) · [OAuth registration](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app)
4. **Google developer project/OAuth client — No paid identity product planned.** For Google sign-in through standard OAuth/OpenID Connect. Configure consent, identity-only scopes and exact callback URLs; verify applicable publishing requirements before launch. We do not need Firebase Authentication, Google Identity Platform or paid Google Cloud compute. [Google identity](https://developers.google.com/identity)
5. **Resend account — Free for a small launch.** Transactional email currently allows 3,000 emails/month and 100/day. A verified sending domain is required for real recipients. The adapter reserves at most 90/day and 2,500/calendar month in D1 before attempting delivery. Failed sends consume reservations; no automatic retry. Use a dedicated account/key and reconcile provider usage: other applications, manual sends and provider billing-period boundaries can consume allowance outside this counter. Provider refusal must fail safely. [Free allowance](https://resend.com/blog/new-free-tier) · [Current pricing](https://resend.com/pricing)
6. **Domain registrar — Paid.** Buying and renewing learntify.lat is separate from free hosting. Check both registration and renewal prices before purchase; no price assumed. Local development needs no domain. Provider subdomains can host a preview, but verified production email needs a domain you control.

## Cloudflare features needed later

- **Turnstile — Free**, before public account creation: up to 20 widgets, 10 hostnames/widget and unlimited challenges. Server-side verification and application rate limits are still necessary. No separate vendor account. [Turnstile plans](https://developers.cloudflare.com/turnstile/plans/)
- **Durable Objects — Free allowance**, when moderated live chat launches. Use SQLite-backed objects. Current compute allowances are 100,000 requests/day and 13,000 GB-seconds/day; storage/read/write allowances also apply. Hibernation and bounded room traffic matter. Indefinite message retention will eventually consume finite storage. [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/)
- **Workers Logs — Limited fit.** Currently 200,000 events/day and three-day retention on Free. This does **not** meet the 14-day diagnostic target. Pricing changes are announced for December 1, 2026, so recheck at deployment. Logging remains disabled in the checked-in Worker configuration while redaction and retention are designed. Never log magic-link URLs, tokens, email bodies or draft contents. The 30-day security-event and 90-day moderation policies require separate bounded application records and cleanup, not an assumption about provider logs. [Logs limits](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)

## Libraries are not external paid services

Better Auth runs inside our server and stores state in D1. React, Vite, Hono, TypeScript, Vitest and Playwright run locally or in CI. We need no hosted auth subscription, AI API, MongoDB cluster, Redis, search provider, analytics subscription, R2 bucket or payment processor for this increment. Optional donation processing will be evaluated separately, including transaction fees.

## Capacity behavior

Free tiers can support development and a bounded initial audience, not a promise of 100,000 simultaneous or daily active learners. At 20 API requests per active learner, 100,000 requests/day represents only 5,000 learner-days before auth, bots or retries. This is an illustration, not a load-test result. Continuous draft sync multiplies writes and must debounce, skip unchanged content and pause safely on quota errors.

To preserve public learning during an API quota outage, publish lesson content as static assets; the current client still fetches lessons from the API, so this fallback is not implemented yet. Admission controls, global quotas, signup safeguards, static lesson fallback and load testing are launch work, not completed guarantees.
